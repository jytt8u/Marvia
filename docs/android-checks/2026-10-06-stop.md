# Отмена и отключение Android VPN — 06.10.2026

Проверка в рабочем дереве после сообщения пользователя: на Android иногда
не удавалось отключить VPN; раньше также отмечался пинг 30–600 мс на LTE
МегаФона. Эти симптомы сами по себе не доказывают единую причину.

## Найденные ошибки

1. Обработчик кнопки главного экрана отправлял остановку только в состоянии
   «Подключено». Во время «Подключаюсь» повторное нажатие попадало в запуск,
   который служба игнорировала как уже выполняющийся. Кнопка теперь отменяет
   и незавершённое подключение.
2. Служба вызывала закрытие Go-ядра и запись SQLite из главного потока Android.
   Если закрытие задерживалось, оно могло задержать обработку следующих
   нажатий. Теперь интерфейс закрывается отдельно, до фоновой очистки.
3. Отмена корутины не прерывала вызов `Mobile.start`. Служба могла уже
   отключаться, пока ядро продолжало ждать панель с переданным TUN. Новый
   `ConnectionAttempt` передаёт отмену в запрос подписки и дозвон, а интерфейс
   создаётся только после успешного подключения к ноде.
4. Опрос ядра проверял остановку до чтения состояния; остановка во время
   чтения могла закончиться поздней публикацией «Подключено». Повторная
   проверка стоит у публикации, чтение JNI вынесено из замка остановки.

Снимок завершённой сессии отделяется от текущей до записи на диск: старая
фоновая запись не стирает счётчики нового подключения. Закрытие TUN выполняется
один раз, чтобы повторный вызов не закрыл чужой переиспользованный дескриптор.
Очистка сетевого ядра и сохранение истории не зависят от отменяемого scope
службы и выполняются независимо друг от друга.

## Проверки

- Тест Android вызывает настоящий обработчик кнопки при «Подключаюсь» и
  проверяет команду остановки. До исправления он воспроизвёл ошибочный переход
  в ветку запуска, после исправления прошёл.
- Go-тесты отменяют зависший запрос чужой подписки и TLS-рукопожатие панели
  VP1, проверяют невозможность повторно запустить отменённую попытку.
- При искусственно зависшем закрытии backend отключение освобождает поток,
  изображающий VPN-интерфейс; повторная остановка не теряет очистку и не
  закрывает backend повторно. Отдельно проверено однократное закрытие
  интерфейса при конкурентных вызовах.
- Android-тест проверяет запись старой сессии после начала новой: история
  сохраняет старые байты, новые счётчики остаются на месте.

Строгий тест с `net.Pipe` также выявил, что endpoint `iobased` не закрывает
переданный ему поток: читатель оставался заблокированным. Мост теперь сам
закрывает предоставленный `io.Closer`, прежде чем чистить стек. Это отдельный
случай потокового интерфейса; Android TUN использует дескриптор `fdbased`.

## Границы результата

Полный `go test -count=1 -timeout=10m ./...` прошёл; проверки с `-race`
пройдены для `mobile`, `internal/tunbridge`, `internal/foreign` и
`internal/client`. Все 74 теста Android прошли. Библиотека gomobile собрана
для ARM64 и ARM, отладочный APK собран через `assembleDebug`.
`go vet ./...` и `go build -o bin/ ./...` завершились успешно.

Это локальные тесты и сборка. Они не воспроизводят конкретный прошлый эпизод
на телефоне пользователя и не подтверждают причину скачков LTE. До состояния
«Подключено» обычный трафик ещё не защищён этим VPN; системная блокировка
подключений без VPN остаётся отдельной настройкой Android.

Изменения не опубликованы и не установлены на телефон. Отладочный APK требует
пересборки библиотеки gomobile вместе с Kotlin: старая библиотека не содержит
нового API отмены. Отладочная подпись отличается от подписи выпуска и не
подходит для обновления установленного выпуска поверх него.
