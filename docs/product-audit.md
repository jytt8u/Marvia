# Marvia: аудит продукта и критерии готовности

16 сентября 2026. База анализа — `ef063348d3aeb11c9689605a58469d3168186d13`
из `jytt8u/marvia`, рабочая ветка `codex/marvia-product`.

## Вывод

У Marvia уже есть основа самостоятельного продукта: ядро клиента, нода,
панель, установка, подписки, Windows и Android. Переписывать всё с нуля
не требуется. Следующий этап — связность сценариев, повторяемая проверка
клиентов и понятная граница между готовыми возможностями и обещаниями.

Идея серого знака соответствует существующей архитектуре тем. Стоит сделать
её сквозным поведением: нейтральное начало, добровольный выбор оформления,
сохранение выбора и простой возврат. Добавлять ещё десятки пресетов сейчас
менее полезно, чем сделать существующие надёжными.

## Что проверено

Изучены структура Go-пакетов, маршруты и интерфейс панели, общая тема,
разбор кода на Kotlin, ресурсы Android, интерфейс Windows, документация,
тесты и workflow сборки. Панель запущена на отдельной локальной базе.
Это аудит продукта и выбранных участков реализации, не полный аудит
криптографии и не испытание на действующей инфраструктуре.

Что уже сделано хорошо:

- `internal/look` хранит общую таблицу оформления; Go генерирует таблицу
  Kotlin, тест проверяет её актуальность. Шрифты и знак вшиты в бинарники.
- В панели текст шаблонов создаётся DOM-узлами, обработчики привязываются
  слушателями, а `web.go` задаёт CSP с nonce и запрет встраивания.
- Тесты проверяют реальные обещания: повтор оплаты не создаёт второй
  доступ, отозванный ключ перестаёт работать, резервная копия восстанавливается.
- Клиентская и серверная логика разделены; Windows и Android используют
  Go-ядро, а не две независимые реализации протокола.

## Исправлено в этой итерации

| Проблема | Изменение |
|---|---|
| Первый экран панели зелёный, хотя исходная тема серая | Нейтральный экран входа, исходный знак в favicon, краткое объяснение идеи |
| Повторная отправка формы входа могла запускать несколько запросов | Кнопка блокируется на время проверки, результат озвучивается через live region |
| В персонализации нет явной точки возврата | «Вернуть серый»; профили и свой фон сохраняются |
| Большинство действий панели — div без клавиатурного поведения | Роль кнопки, Tab, Enter и пробел; подписи цвета и направления света, состояние выбора |
| При выборе темы фокус исчезает вместе с DOM | Возврат фокуса на выбранную тему, цвет, свет, ползунок и новые действия |
| В светлой теме часть текста оставалась белой | Цвет текста и полос прокрутки следует текущей теме |
| Tab уходил под диалог, а Escape оставлял подтверждение незавершённым | Изоляция фокуса, возврат к исходной кнопке, завершение отмены; регрессионный тест |
| Группы видов доступа не имели отдельных подписей | Fieldset с легендой и подпись каждого флажка |
| Копирование кода молча не работало при отказе буфера | Сообщение об успехе или отказе в панели и Windows; код не обрезается |
| Импорт при потере фокуса перерисовывал кнопку до клика | Явное применение кнопкой или Enter; повреждённый текст сохраняется для исправления |
| `55junk` в коде темы принималось JavaScript, но не Kotlin | Строгая одинаковая проверка поля глубины, регрессионные тесты |
| Имена вроде `constructor` принимались за пресет | Проверка собственных ключей таблиц; сохранённая тема не ломает запуск |
| Иконки Android смешивали зелёную M и старый синий щит | Исходный серый знак в обычной и адаптивной иконке, его силуэт в монохромной и уведомлении |
| Архитектурный документ обещает отдельный отзыв устройств и gRPC/mTLS | Добавлена явная отметка об историческом характере документа и ссылка на актуальное поведение |

В CI добавлены исполняемые JavaScript-тесты общего движка и диалогов. Раньше Go-тесты
в основном проверяли структуру таблиц как текст и не ловили эти два дефекта.

## Следующие приоритеты

### 1. Повторяемый путь от установки до восстановления

Самый важный сценарий: чистый сервер → панель → нода → подписка → подключение
Windows и Android → отключение ноды → переподключение → восстановление
панели из копии. Прогонять перед релизом, записывать версии и результат каждого
шага. Автотесты отдельных пакетов не заменяют этот сценарий.

Критерий: новая установка без правки исходников и ручного копирования ключей;
после отказа ноды и восстановления панели пользователь получает понятное
состояние и может продолжить работу.

### 2. Первый запуск новой Android-проверки в GitHub Actions

Исходный `check.yml` не собирал Android. Локальный первый запуск Gradle выявил
старый `marvia.aar`: текущему
Kotlin нужны `UpdateVersion` и `UpdateURL`, которых в старом бинарнике нет.
Методы в исходниках Go есть; пересборка AAR из актуального кода устранила
ошибку. Kotlin-тесты и debug APK после этого успешно собраны.

Добавлен отдельный Android job: CI собирает AAR из того же commit, запускает
Kotlin-тесты, компилирует ресурсы и debug APK, сохраняет отчёты тестов.
Workflow проверен actionlint. Изменения пока локальные; удалённый запуск
GitHub Actions ещё не выполнялся. После публикации ветки проверить его результат.
Релизная подпись остаётся отдельным процессом.

### 3. Проверка поведения на устройствах

Android: запуск после перезагрузки, отзыв VPN-разрешения, смена Wi-Fi/LTE,
сон, Always-on VPN, ошибка обновления подписки. Windows: права администратора,
драйвер, выход из сна, конфликт прокси, обновление поверх предыдущей версии.

Критерий: состояние «подключено» соответствует реальному соединению;
ошибка объясняет следующее действие; повторная попытка доступна без перезапуска.
После изменения иконок проверить launcher и уведомления на Android 7, 8 и 13+.

### 4. Развести личную тему и бренд продавца

Перенос `MV-…` уже работает между клиентами. Он не является доставкой
полноценного бренда через подписку. Для такого продукта нужно отдельно
определить имя сервиса, поддержку, логотип, безопасный формат ресурсов,
подпись/проверку происхождения и приоритет личного выбора пользователя.

Критерий: смена подписки не уничтожает личную тему; пользователь видит,
кому принадлежит доступ и куда обратиться при проблеме. Реализацию начинать
с одного законченного сценария, а не с набора неработающих полей.

### 5. Доступность и сопровождение интерфейсов

Панель — один большой HTML-файл с шаблоном, словарями, состоянием и API;
Windows содержит параллельный интерфейс. Продолжить небольшими извлечениями
общих частей и браузерными тестами, сохранив встроенную раздачу без CDN.
Фокус диалогов и подписи видов доступа исправлены. Дальше проверить длинные имена, пустые
состояния, ошибки сети, контраст с пользовательскими фонами и масштаб текста.

Критерий: ключевые сценарии проходят без мыши; выбранный цвет не скрывает
ошибки и текст; изменение общей темы проверяется во всех клиентах.

### 6. Документация и релизный комплект

Архитектурный документ нужно сверить с кодом целиком: в нём остаются старые
схемы и проектные намерения. `ServeAsset` кеширует файлы на год как immutable,
хотя публичные имена ресурсов не содержат версии — перед следующей сменой
ресурсов нужен fingerprint или условная перепроверка кеша.

Подготовить векторный мастер знака, комплект иконок и проверенные изображения
экранов. Правила бренда — в [brand.md](brand.md). Перед стабильным релизом
зафиксировать совместимость API/подписок и отдельно провести review
протокола и модели угроз. Успешные тесты не доказывают эти свойства целиком.

## Проверки этой итерации

Дополнение от 17 сентября: Android и Windows показывают отклик готового
туннеля отдельно от времени подключения. Добавлен служебный Ping yamux,
без изменения формата VP1. Отмена ограничена контекстом, не закрывает
рабочую сессию и не допускает накопления параллельных зависших замеров.
Проверены отсутствие подмены на 600 мс подготовки, передача обоих полей
в клиенты и отмена запроса. Пересобраны AAR, Windows и debug APK.
Реальный маршрут РФ → ОАЭ пока не измерялся; ускорение сети не заявляется.

- `go test ./...`, `go vet ./...`, сборка всех Go-команд на Windows.
- `node --test internal/look/look.test.cjs internal/panel/web.test.cjs`: 8 тестов;
  исходный вид, сохранение,
  перенос всех 28 видов, отказ повреждённых кодов, восстановление битых настроек,
  недоступное хранилище, завершение подтверждений и синтаксис обоих интерфейсов.
- `gomobile bind` для ARM64 и ARM; `:app:testDebugUnitTest` и
  `:app:assembleDebug` после пересборки ядра — успешно, 18 Kotlin-тестов пройдены. Визуальные изменения
  Android скомпилированы, на устройстве пока не проверены.
- Браузер: вход, выбор темы клавиатурой, сохранение после перезагрузки,
  ошибочный и корректный импорт, копирование, сброс, русский/английский,
  визуальная проверка нейтрального, цветного и светлого оформления;
  Tab/Shift+Tab/Escape в диалоге, возврат фокуса, подписи флажков.
- `actionlint` для `.github/workflows/check.yml` — без ошибок.

Не выполнялись: развёртывание на боевом сервере, публикация релиза,
нативные испытания туннеля на устройствах и полный security review.
