# Проверка безопасности — 30 сентября 2026

Проверен стабильный код после `d55b625`: загрузка подписок, обработка ошибок,
права API панели, фильтрация целей ноды, выбор приложений Android и управление
соединением Windows. Подтверждения — локальные тесты с искусственными ключами
и временными HTTP-серверами. Живые серверы и чужие устройства не атаковали.

## Подтверждённые проблемы и исправления

| Проблема | Условия и последствия | Исправление |
|---|---|---|
| Токен в ошибке перенаправления | Ответ панели с неверным `Location` включал адрес подписки в причину ошибки; она могла попасть в журнал и пересланную диагностику | Обезличивание причины разбора и вложенных `url.Error`; цепочка причин остаётся доступной через `errors.Is` |
| Потеря TLS при загрузке подписки | Сервер HTTPS мог перенаправить запрос с токеном на HTTP; наблюдатель сети мог прочитать токен и изменить ответ | Переход после любого HTTPS-запроса на незашифрованный адрес запрещён для подписки, списка обхода и чужой подписки |
| Расширение списка приложений Android | После удаления всех выбранных приложений пустой allowlist Android означал весь телефон, включая приложения, которые пользователь не выбирал | Подключение останавливается до `establish()`; оставшиеся установленные пакеты продолжают работать |
| Гонка отмены подключения Windows | Старый отменённый запрос мог поставить `idle` поверх нового соединения; старые события надзора могли менять его ноду и состояние | Состояние привязано к контексту конкретной попытки; адаптеры создаются и удаляются последовательно |

Первые две проблемы требуют соответствующего ответа сервера подписки. Это
не означает, что внешний наблюдатель способен самостоятельно подменить
исправно проверяемое HTTPS-соединение. Следов реальной утечки этот аудит
не устанавливает. Токены, уже переданные в чужую диагностику, следует отозвать.

Исходные HTTP-подписки оставлены для совместимости: они остаются
незашифрованными и должны быть заменены владельцем на HTTPS. Защита
перенаправлений не превращает начальный HTTP в безопасный канал.

## Проверки

- Полный `go test ./...` и `go vet ./...` проходят на Windows.
- Проверка в двух настоящих процессах Windows подтверждает, что повторный
  запуск открывает существующее окно через IPC. Отдельные тесты проверяют
  ограничения передаваемой ссылки и освобождение блокировки при выходе.
- `govulncheck v1.8.0 ./...`: Windows/amd64 и Linux/amd64, Go 1.26.6.
  Достижимых известных уязвимостей и уязвимых импортированных пакетов нет.
  Есть предупреждение [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)
  о `x/crypto/openpgp`; этот пакет кодом Marvia не импортируется и не вызывается.
- Четыре фаззера VP1 по 15 секунд с двумя рабочими процессами: кадры,
  добивка, запросы, датаграммы. Всего 3 808 356 исполнений, сбоев нет.
- Регрессионные тесты воспроизвели утечку токена, потерю TLS, удалённый
  выбор приложений и перезапись новой сессии отменённой попыткой до исправления.
- Проверки перенаправлений дополнительно покрывают закреплённые IP,
  список обхода, чужие подписки и сохранение ограничения числа переходов.
- Тесты Android проверяют удалённые пакеты, смешанный список и запрет
  включения самого клиента в свой туннель. Все локальные Kotlin-тесты проходят.

Проверка гонок `-race` для загрузки подписок добавлена в Linux CI; локально
здесь она не запускалась. Исправление выбора приложений Android проверено
в исходниках и тестах, но обновлённый APK в рамках этой проверки не установлен.

## Комплект Windows

В первом предварительном комплекте не было `wintun.dll`: окно открывалось,
но создание адаптера завершалось ошибкой отсутствующей библиотеки. Исправлено
упаковкой EXE вместе с официальной DLL и её лицензией в `marvia-windows.zip`.
Это ошибка поставки, а не подтверждённая уязвимость протокола.

Архив Wintun 0.14.1 сверен с SHA256, опубликованным на
[сайте Wintun](https://www.wintun.net/). Подпись извлечённой DLL на Windows —
`Valid`, издатель `WireGuard LLC`. Windows успешно загрузила библиотеку;
экспорт `WintunCreateAdapter` доступен. Адаптер при этой проверке не создавали
и реальное подключение этим тестом не подтверждали. Повреждённый архив
отклоняется упаковщиком до создания комплекта.

Android документирует поведение пустого списка и проверку установленных
пакетов в [VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder#addAllowedApplication(java.lang.String)).

## Оставшиеся границы защиты

- Независимого аудита криптографии и полной проверки серверного окружения
  не проводилось. Тесты и фаззинг не доказывают отсутствие остальных ошибок.
- Ключи в клиентском хранилище защищены правами ОС, без отдельного шифрования
  Windows DPAPI / Android Keystore. Вредоносная программа с доступом к этим
  файлам или root/admin может украсть доступ. Android backup выключен.
- Windows EXE пока не подписан сертификатом издателя; SmartScreen может
  предупреждать. Хеш файла помогает проверить целостность, но не заменяет подпись.
- Нужна отдельная проверка DNS/IPv6 и поведения при смене Wi-Fi/LTE на
  реальном телефоне. Телефон во время этой проверки не подключён по USB.
- Точечный просмотр API и фильтра целей не является полноценным тестом
  устойчивости панели и нод к распределённой нагрузке или DDoS.

У документа нет рейтинга «безопасность в процентах»: он перечисляет проверенные
сценарии, подтверждённые ошибки и ограничения проверки.
