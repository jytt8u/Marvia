# Свой VPN с нуля: тестовая установка Marvia

Инструкция от 30 сентября 2026 года. Здесь — отдельный чистый VPS для проверки проекта, а не переустановка работающей панели. База для такого стенда — `v0.12.2`. Это прежний релиз, а не обещание отсутствия ошибок или всех исправлений безопасности из текущей разработки. Следующая разработка — `0.13.0-alpha.1`; её пока нельзя скачать как выпущенную версию. Выпуск 1.0 отложен.

Если Marvia уже стоит и подключается, сохрани эту установку. Номер версии в GitHub не означает, что нужно немедленно менять сервер, APK, EXE или базу. Для проверки нового выпуска сначала нужен отдельный стенд и резервная копия.

## 1. Что понадобится

- Один VPS с публичным IPv4 и Ubuntu 24.04 LTS. VPS — удалённый компьютер, который работает постоянно. Нужен доступ по SSH с правами администратора; Linux-контейнер без systemd для этой инструкции не подходит.
- Домен, которым ты управляешь, например `example.com`. Используем поддомен `panel.example.com`.
- Windows-компьютер или Android-телефон для проверки подключения.
- Менеджер паролей для админского токена, ключей и ссылок подписки.

На одном сервере можно поставить и панель, и ноду. **Панель** выдаёт доступы и подписки; **нода** передаёт трафик в интернет. Второй VPS нужен, когда потребуется запасная нода или другое расположение. Для первых проверок он не обязателен.

| Служба на первом VPS | Порт | Зачем |
|---|---|---|
| SSH | фактический порт SSH, обычно TCP 22 | управление сервером |
| Проверка сертификата панели | TCP 80 | получение и продление TLS-сертификата |
| Панель | TCP 8443 | браузер, подписки, управление нодами |
| Нода | TCP 443 | VPN-подключения |

Порты здесь указаны явно: **автоматического подбора свободного порта в установщике v0.12.2 нет**. И панель, и нода по умолчанию хотят занять 443. Поэтому панели ниже передаём `--port 8443`, а ноде оставляем 443. UDP для этой базовой установки открывать не нужно; для будущего QUIC понадобятся отдельная настройка и проверка.

## 2. Домен и первый вход

В DNS домена создай запись:

```text
Тип: A
Имя: panel
Значение: публичный IPv4 твоего VPS
```

Сначала используй прямую DNS-запись без проксирования CDN. Запись `AAAA` добавляй только если у VPS действительно есть настроенный и доступный IPv6. Неверная `AAAA` может направить часть клиентов на недоступный адрес. DNS панели не является настройкой DNS внутри VPN — это разные вещи.

На своём компьютере открой терминал и подключись, заменив адрес и пользователя данными своего VPS:

```bash
ssh root@IP_ТВОЕГО_VPS
```

Перед подтверждением первого подключения сверь отпечаток SSH-ключа с консолью провайдера. Используй SSH-ключ для дальнейшего входа; настройку описывает [документация Ubuntu по OpenSSH](https://ubuntu.com/server/docs/how-to/security/openssh-server/). Не отключай рабочий способ входа, пока новый ключ не проверен во второй SSH-сессии.

На сервере, от root:

```bash
apt-get update
apt-get install -y ca-certificates curl tar openssl iproute2 less
timedatectl set-ntp true
getent ahostsv4 panel.example.com
ss -lntp
```

В результате `getent` должен показать IPv4 этого VPS. В `ss` проверь, что 80, 443 и 8443 свободны. Если их занимает nginx, другая панель или VPN, сначала выбери отдельный чистый VPS; не останавливай незнакомую службу на рабочем сервере.

Разреши нужные TCP-порты в сетевом экране провайдера и в серверном firewall. Если UFW уже используется, пример для стандартного SSH на 22:

```bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 8443/tcp
ufw status
```

При другом порте SSH замени 22 до изменения правил. Эти команды добавляют правила; они не включают UFW. Перед включением firewall убедись, что есть доступ через консоль провайдера и разрешён твой реальный порт SSH.

## 3. Скачать именно установщик и ядро v0.12.2

Команды ниже выполняются **только на чистом сервере**. Вместо `panel.example.com` далее используй свой настоящий поддомен.

```bash
set -eu
umask 077
mkdir -p /root/marvia-install-v0.12.2
cd /root/marvia-install-v0.12.2

TAG=v0.12.2
RELEASE="https://github.com/jytt8u/marvia/releases/download/$TAG"
case "$(uname -m)" in
  x86_64|amd64) ARCH=amd64 ;;
  aarch64|arm64) ARCH=arm64 ;;
  *) echo 'Для этой архитектуры готовой сборки нет'; exit 1 ;;
esac

curl --proto '=https' --tlsv1.2 -fsSL "$RELEASE/install-panel.sh" -o install-panel.sh
curl --proto '=https' --tlsv1.2 -fsSL "$RELEASE/SHA256SUMS" -o SHA256SUMS
awk '$2 == "install-panel.sh" || $2 == "*install-panel.sh"' SHA256SUMS > install-panel.sha256
test -s install-panel.sha256
sha256sum --check install-panel.sha256

less install-panel.sh
```

После просмотра выйди из `less` клавишей `q`. Если скачивание не прошло, суммы нет или она не сошлась — остановись. Не убирай проверку ради продолжения. Сумма защищает от повреждения и несоответствия файлов; сама по себе она не является независимым аудитом или подписью издателя.

Запуск, уже с правильным доменом:

```bash
sh install-panel.sh \
  --domain panel.example.com \
  --port 8443 \
  --from "$RELEASE/marvia_linux_$ARCH.tar.gz"
```

Скрипт установит панель в `/opt/marvia`, создаст службу `marvia-panel`, служебного пользователя `marvia` и получит сертификат Let's Encrypt. При желании добавь `--email ТВОЯ_ПОЧТА`. Панель должна открываться по **`https://panel.example.com:8443`**, без ошибки сертификата.

**Нюанс старого установщика:** адрес `--from` закрепляет архив ядра. При этом приложения Android и Windows он может скачать через `releases/latest`, а не из указанного тега. Не считай такую установку полностью закреплённой на v0.12.2. Следующий шаг позволяет не смешивать эти клиенты с тестовой базой.

Не запускай эту команду поверх существующего `/opt/marvia`. Отказ установщика в этом случае — защита базы, а не повод удалить каталог.

## 4. Сохранить вход и проверить версии

В конце установщик покажет админский токен. Сохрани его в менеджере паролей и введи на странице панели. Этот токен даёт управление всей установкой; он не является клиентским VPN-ключом.

```bash
/opt/marvia/marvia-panel -version
/opt/marvia/dist/marvia-node -version
systemctl is-active marvia-panel
curl --proto '=https' -fsS https://panel.example.com:8443/healthz
```

Бинарники ядра должны сообщить `v0.12.2`, служба — `active`, а `/healthz` — ответ без ошибки HTTPS. Не используй `curl -k`: он скрывает проблему доверия сертификату.

Для тестовых клиентов открой [релиз v0.12.2](https://github.com/jytt8u/marvia/releases/tag/v0.12.2) и бери файлы из его списка вложений. Не нажимай «последний релиз» для такого стенда. Если нужного файла нет, остановись и уточни доступный комплект: не переименовывай файл другой версии в v0.12.2.

В v0.12.2 есть `marvia-android.apk` с отдельным `marvia-android.apk.sha256`, а также `marvia-windows.exe`, включённый в `SHA256SUMS`. Пока приложения из `/latest` не сверены, не раздавай их из панели. На новом стенде замени их файлами нужного тега:

```bash
cd /root/marvia-install-v0.12.2
RELEASE=https://github.com/jytt8u/marvia/releases/download/v0.12.2
curl --proto '=https' --tlsv1.2 -fsSL "$RELEASE/marvia-windows.exe" -o marvia-windows.exe
awk '$2 == "marvia-windows.exe" || $2 == "*marvia-windows.exe"' SHA256SUMS > windows.sha256
test -s windows.sha256
sha256sum --check windows.sha256

curl --proto '=https' --tlsv1.2 -fsSL "$RELEASE/marvia-android.apk" -o marvia-android.apk
curl --proto '=https' --tlsv1.2 -fsSL "$RELEASE/marvia-android.apk.sha256" -o marvia-android.apk.sha256
APK_SHA=$(awk 'NR == 1 { print $1 }' marvia-android.apk.sha256)
printf '%s  marvia-android.apk\n' "$APK_SHA" | sha256sum --check

install -m 644 marvia-windows.exe /opt/marvia/dist/marvia-windows.exe
install -m 644 marvia-android.apk /opt/marvia/dist/marvia-android.apk
printf '%s\n' '0.12.2' > marvia-client.version
install -m 644 marvia-client.version /opt/marvia/dist/marvia-windows.exe.version
install -m 644 marvia-client.version /opt/marvia/dist/marvia-android.apk.version
```

Здесь также действует `set -eu` из предыдущего шага: ошибка скачивания или суммы должна остановить выполнение. Если открылась новая SSH-сессия, сначала выполни `set -eu`. Метки `.version` исправляем отдельно: версия панели не доказывает версию APK/EXE. Сверка суммы APK не подтверждает совместимость его подписи с уже установленным приложением. Отдельный Windows EXE остаётся неполным комплектом — добавление Wintun описано ниже.

В тестовой панели **не нажимай «Обновить до последнего релиза»**: механизм старого выпуска выбирает актуальный GitHub-релиз и не закрепляет твой стенд на v0.12.2.

## 5. Добавить первую ноду на тот же VPS

В панели открой **«Ноды» → «Добавить ноду»**. Получишь установочную команду с одноразовым приглашением. Оно действует час и разрешает одну регистрацию ноды. Это не админский токен; не пересылай приглашение посторонним.

Пример формы команды, **не готовая ссылка**:

```bash
curl -fsSL https://panel.example.com:8443/install/ПРИГЛАШЕНИЕ_ИЗ_ПАНЕЛИ | PORT=443 NAME=personal-1 sh
```

Используй реальную команду панели. Для предварительного просмотра можно скачать её скрипт в приватный файл, прочитать его и запустить через `PORT=443 NAME=personal-1 sh имя_файла`. Одноразовый адрес останется в истории терминала; после установки он уже использован. Не сохраняй полученный скрипт с приглашением в GitHub.

На чистом VPS порт 443 должен быть свободен, потому что панель стоит на 8443. Скрипт создаст ключи ноды, зарегистрирует её, поставит службу `marvia-node`. Приватные ключи остаются на сервере. Имя страны можно указать переменной `COUNTRY`; не рассчитывай на её автоопределение в этом старом выпуске.

```bash
/opt/marvia-node/marvia-node -version
systemctl is-active marvia-node
ss -lntp
```

В панели нода должна выйти на связь. **Проверь её адрес:** он должен быть публичным IPv4 VPS с портом 443. Для регистрации используй публичный домен панели, а не `localhost` или `127.0.0.1`. Если при установке на том же VPS адрес определился как петлевой/частный, исправь его в карточке ноды на публичный `IP:443`; такой адрес клиент с телефона не сможет использовать.

Установщик проверяет доступность сайта прикрытия по TLS 1.3. Если проверка остановилась, сначала проверь исходящую сеть VPS. Не меняй криптографию или проверку сертификатов, чтобы спрятать ошибку.

## 6. Выпустить доступ себе и подключить клиент

В разделе клиентов/подписчиков создай доступ с меткой «Мой тест». Для начала задай ограниченный срок и разумную квоту; выбери собственный тип доступа `vp1` для приложения Marvia. VLESS/Trojan добавляй отдельно, если нужен совместимый сторонний клиент: их наличие не делает каждый клиент совместимым с любым видом подписки.

После выдачи сохрани два вида ссылки:

- **`marvia://…`** — доступ для приложения Marvia. В нём есть секретная часть и адрес подписки.
- **`https://panel.example.com:8443/sub/…`** — URL подписки. Он также секретный: токен в адресе позволяет получить конфигурацию. Импортируй его только в клиент, который поддерживает формат выданной подписки.

Админский токен в клиент не вставляй. Подписку не публикуй в README, обсуждении или скриншоте. Если ссылка уже попала в публичный доступ, отзови/смени соответствующий доступ в панели и импортируй новую ссылку.

### Windows

У v0.12.2 отдельный EXE не является готовым комплектом: ему нужен `wintun.dll` рядом. Возьми DLL из **официального архива [Wintun](https://www.wintun.net/)**, вариант `amd64` для Windows-клиента x64. Проект Wintun предоставляет подписанные готовые DLL; не скачивай их с сайтов «DLL для исправления ошибок».

Проверь подпись в PowerShell:

```powershell
Get-AuthenticodeSignature .\wintun.dll | Format-List Status, SignerCertificate
```

Ожидается `Valid` и подпись официального издателя. Запускай Marvia из папки с DLL; для создания адаптера нужны права администратора. Также нужен WebView2 Runtime. Новый установщик с готовым комплектом пока относится к локальной alpha-разработке и не объявлен стабильной версией.

Перед запуском выйди из других VPN-клиентов и старых копий Marvia. Если Marvia сообщает о системном прокси Hiddify, проверь его настройки: оставшийся прокси означает, что браузер может использовать другой путь. Прокси, настроенный организацией или родительским контролем, самовольно не меняй.

### Android

Бери APK выбранного выпуска из проверенного источника. При первом подключении Android покажет системное разрешение на VPN. Подтверди его для Marvia. Для полного туннеля проверь, что выбран охват всех нужных приложений, а исключения и обход отдельных стран соответствуют тому, что ты действительно хочешь.

Если на телефоне уже стоит 1.0/1.0.1, переключение релиза GitHub не означает, что надо понизить APK: Android сравнивает внутренний `versionCode` и обычно не разрешает установку старой версии поверх новой. Не удаляй установленное приложение только ради старого APK или APK с другой подписью: так можно потерять сохранённые ключи и настройки. Сначала выясни происхождение обоих APK и сохрани доступ. Рабочие клиенты на своих устройствах оставь до отдельной проверки совместимости.

## 7. Проверить подключение, а не только зелёную кнопку

Сначала выключи VPN и запиши исходные значения: публичный IPv4, доступность IPv6, DNS-резолверы, время открытия обычного сайта и пинг. После подключения повтори те же проверки на той же сети.

На Windows можно измерить пинг до **публичного адреса своей ноды**:

```powershell
ping -n 20 IP_ТВОЕЙ_НОДЫ
```

Проверяй этот адрес до подключения, чтобы увидеть маршрут провайдера до VPS. ICMP могут фильтровать, поэтому отсутствие ответа не равно отказу VPN. Пинг сайта после подключения содержит маршрут через VPS и не обязан совпадать с «откликом ноды» в приложении.

В браузере проверь публичный IPv4, затем [IPv6-связность](https://test-ipv6.com/) и [DNS-резолверы](https://www.dnsleaktest.com/). Для выбранного полного туннеля публичный адрес должен соответствовать выходу ноды; домашний/мобильный IPv6 не должен незаметно остаться отдельным выходом. В IPv4-режиме отсутствие IPv6 допустимо, но его прямой выход через провайдера — повод остановить проверку. Список DNS — дополнительный сигнал, а не окончательное доказательство пути каждого запроса: настройки браузера, DNS-over-HTTPS и явные исключения меняют результат.

Затем проверь:

1. Пять отключений и подключений подряд: сохрани время каждого успешного подключения и ошибки.
2. Сон/пробуждение Windows; блокировку и разблокировку Android.
3. На Android переход Wi-Fi → мобильная сеть → Wi-Fi.
4. Несколько минут обычной работы без второго VPN и без фоново запущенного теста скорости.
5. Перезапуск тестового VPS и возврат обеих служб в `active`.

Сравни Wi-Fi и мобильную сеть отдельно. Скачки пинга 70–500 мс могут быть связаны с радио, нагрузкой, маршрутом или самим приложением; одной цифры недостаточно, чтобы обвинить оператора. Не меняй сразу несколько настроек — иначе не поймёшь, что помогло.

## 8. Диагностика без публикации секретов

На тестовом сервере:

```bash
systemctl is-active marvia-panel marvia-node
journalctl -u marvia-panel -n 30 --no-pager
journalctl -u marvia-node -n 30 --no-pager
timedatectl status
```

Проверка ноды, закреплённая на исходниках той же тестовой версии:

```bash
curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/jytt8u/marvia/v0.12.2/scripts/node-check.sh \
  -o /root/marvia-install-v0.12.2/node-check.sh
less /root/marvia-install-v0.12.2/node-check.sh
sh /root/marvia-install-v0.12.2/node-check.sh
```

Этот скрипт проверяет службы, права ключей, порт, часы и исходящую связность, ничего не меняя. Он не печатает содержимое `env` и приватные ключи. Перед отправкой любых журналов всё равно просмотри результат: не прикладывай полные `marvia://…`, адреса `/sub/…`, приглашения, содержимое файлов `env` и `node.key`.

| Что произошло | Что проверить первым |
|---|---|
| Панель не открывается по HTTPS | DNS A/AAAA, порты 80/8443, журнал панели, доверие сертификату |
| Нода не появляется | срок приглашения, доступ к панели, `marvia-node`, публичный адрес ноды |
| `wintun.dll` не найден | полный Windows-комплект, DLL рядом с EXE и правильная архитектура |
| «Подключено», но сайты не открываются | исходящую сеть VPS, DNS/IPv6, остаточный системный прокси |
| Скачет пинг | исходный пинг без VPN, сеть Wi-Fi/LTE, загрузку VPS, время суток |

## 9. Копии и безопасное обновление

Нажми в панели **«Копия базы»** и храни скачанный файл вне VPS в зашифрованном хранилище. Он содержит данные доступов и токены подписок. В `/opt/marvia/backup` панель по умолчанию также создаёт ежедневные копии и хранит семь; копия на том же VPS не заменяет внешнюю.

Не копируй работающий `panel.db` одним `cp`: SQLite использует WAL, и такой файл может не содержать последних изменений. Используй кнопку копии или штатный механизм резервирования панели. Для полного восстановления нужны также секреты/настройки панели и ноды, сохранённые приватно, и описание версии бинарников, DNS и служб.

Перед обновлением:

1. Сделай свежую копию базы и снимок VPS у провайдера; запиши текущие версии.
2. Испытай выбранный выпуск на отдельном стенде: установка, подключение, перезапуск, обновление и возврат.
3. Проверь совместимость подписок, ключей, базы, Android-подписи и Windows-комплекта.
4. Обновляй рабочую установку только после этих проверок, с понятным способом вернуть согласованную копию базы и бинарников.

Снижение публичного номера версии проекта не является автоматическим понижением формата базы. Рабочую базу новой панели нельзя вслепую передавать старому бинарнику.

## Если нужен только личный VPN без панели Marvia

Альтернатива — WireGuard на одном VPS с официальным клиентом и отдельным ключом для каждого устройства. Панель, подписка Marvia и домен для сертификата панели тогда не требуются. При этом нужны настройка маршрутизации, DNS, forwarding и firewall на сервере. Начни с [официальной инструкции WireGuard](https://www.wireguard.com/quickstart/) и раздела [WireGuard в документации Ubuntu](https://ubuntu.com/server/docs/how-to/wireguard-vpn/) — в нём есть схемы peer-to-site и default gateway. Не запускай демонстрационный скрипт из Quick Start для постоянного личного доступа: он обозначен авторами как небезопасный демонстрационный транспорт.

Выбор зависит от задачи: собственные клиенты, панель и выдача доступов — стенд Marvia; один личный туннель на своих устройствах — отдельная конфигурация WireGuard. Ни тот, ни другой вариант не обещает анонимность, отсутствие блокировок или минимальный пинг в любой сети. Владелец VPS и внешний маршрут остаются частью доверия.
