# VP1 Fast — experimental-1

**Отдельный экспериментальный вариант VP1 с AES-256-GCM внутри Noise IK.**
Реализованы хендшейк, защищённый поток и локальный стенд. В выпущенных
приложениях, подписках и слушателях нод выбора Fast пока нет.

VP1 расшифровывается как **Veil Protocol, версия 1**. Veil — прежнее имя
проекта; Marvia — нынешнее название продукта. Fast — название эксперимента,
а не обещание ускорения на любом устройстве.

## Что изменилось

| Параметр | VP1 | VP1 Fast experimental-1 |
|---|---|---|
| Noise | `Noise_IK_25519_ChaChaPoly_BLAKE2s` | `Noise_IK_25519_AESGCM_BLAKE2s` |
| Шифрование Noise | ChaCha20-Poly1305 | AES-256-GCM |
| Prologue | `veil/vp1` | `marvia/vp1-fast/experimental-1` |
| Обмен ключами / хеш | X25519 / BLAKE2s | X25519 / BLAKE2s |
| Внешний транспорт стенда | TLS 1.3 | TLS 1.3 |
| Кадры и добивка | Текущий формат VP1 | Тот же формат после отдельного хендшейка |
| Совместимость с обычной нодой VP1 | Да | Нет; нужна явная поддержка обеих сторон |

AES-GCM предоставляется библиотекой Noise через стандартную криптографию Go.
Самодельных шифров и ручного управления nonce нет. Оба слоя шифрования
сохранены. Аппаратное ускорение AES может уменьшить затраты, но результат
зависит от процессора и нагрузки. Замена AEAD сама по себе не доказывает
более высокую безопасность или устойчивость к блокировкам.

## Граница эксперимента

Стороны явно вызывают `ClientFastHandshake` и `ServerFastHandshake` из
`internal/vp1`. Автоматического согласования, перебора шифров и отката к VP1
нет. Различающиеся набор Noise и prologue входят в хендшейк: обычный VP1 и
Fast не устанавливают соединение друг с другом даже с теми же ключами.

Вызывающий код обязан установить и проверить внешний TLS до хендшейка,
передать доверенный публичный ключ ноды клиенту и закрыть соединение при
ошибке. Сервер требует непустой `Authorizer` и общий `ReplayGuard` для
соединений одного слушателя. Создание новой памяти повторов на каждый вход
не защищает от повторов между соединениями. `AllowAll` допустим только в тестах.

Новый слушатель следует снабжать отдельными ключами и явно помечать
экспериментальным. Текущие ноды, ключи подписок и настройки приложений
этой правкой не переводятся на Fast. REALITY, QUIC, WebSocket, мультиплексор
и мобильный TUN с Fast в этой серии не проверялись.

## Проверки

- Передача больших сообщений в обе стороны без изменения содержимого.
- Отклонение подмены шифротекста и тега, повторов и перестановки кадров,
  а также кадра из другой сессии; при отказе полезные данные не выдаются.
- Отклонение повторного хендшейка, времени вне окна и неразрешённого клиента.
- Отклонение неверного ключа ноды и подменённого закрытого ключа клиента.
- Отказ при смешивании VP1 и Fast в обоих направлениях.
- Отказ Fast API без проверки доступа или памяти повторов.

Это автоматические тесты реализации, **не независимый криптографический аудит**.

## Измерить самостоятельно

```sh
go test ./internal/vp1 ./cmd/marvia-bench
go run ./cmd/marvia-bench -experimental -rounds 7 -mib 512 -echoes 1000 -revision YOUR_COMMIT > fast.jsonl
```

Без `-experimental` состав CLI-бенчмарка остаётся прежним. Стенд поднимает
клиента и сервер на loopback, проверяет доставку данных, использует одинаковый
TLS и меняет порядок режимов между прогонами. Время установления соединения
не входит в пропускную способность. Скорость в `MB_per_second` — десятичные
МБ/с; объём `-mib` — МиБ.

[Замеры 27.09.2026 и исходные данные](benchmarks/2026-09-27-vp1-fast/README.md).
Перед включением в клиент нужны замеры на Android ARM64, проверка расхода
батареи, интеграция с нодой и подписками и отдельный разбор безопасности.
